---
title: "導入手順（30分）"
---

特定のAIツール専用ではありません。**「エージェントごとに指示書ファイルを置ける」仕組み**なら流用できます。ここではファイルベースの構成を前提に書きます。

## Step 1. 置き場所を作る（5分）

```
<あなたのプロジェクト>/
├── <司令塔ファイル>        ← 00-core.md をコピー
├── agents/
│   ├── generator.md        ← コピー
│   ├── evaluator.md        ← コピー
│   └── executor.md         ← コピー
└── experiments/            ← 空のフォルダを作るだけ
```

`handoff.md` は毎回コピーして使う雛形なので、手元に置いておけば十分です。

## Step 2. 司令塔の `<>` を埋める（10分）

`00-core.md` の中で埋める箇所は**2つだけ**です。

**1. 目的（1行）**

達成したい状態を1つだけ書きます。「正しく判断する」のような抽象的な目的だと、下の役割分担が全部ぼやけます。

```
悪い例: 良い判断をする
良い例: 毎週1つ、市場で検証する
```

**2. パイプラインの発動タイミング**

「どの場面で自動的に 生成→評価 を挟むか」を書きます。ここを決めておかないと、結局いつも人間が思いついた時だけ動く仕組みになります。

```
| 場面 | 発動 |
|------|------|
| 金銭が動く前 | 生成役 → 評価役 → 人間が決定 |
| 外部に公開する前 | 生成役 → 評価役（ファクトチェック）→ 人間が決定 |
```

## Step 3. 評価役を「独立起動」できる形にする（10分）★最重要

**このキットで唯一、妥協すると全部が無意味になる箇所です。**

評価役は、**会話履歴を引き継がない別プロセスとして起動**する必要があります。

- ✅ サブエージェント機能・別セッション・別APIコールとして呼ぶ
- ❌ 同じ会話の中で「じゃあ次は評価役として厳しく見て」と役割を切り替える

後者だと、それまでのやり取りが全部文脈に残っているため、**どれだけプロンプトで「厳しく」と書いても独立性は生まれません。**

使っているツールにサブエージェント機能が無い場合は、**新しい会話を開いて `evaluator.md` の内容を貼り付ける**だけでも成立します。

## Step 4. 最初の1回を回す（5分）

いきなり本番の判断に使わず、**既に結果が出ている過去の判断**で試すのがおすすめです。

1. 過去に自分が決めた案件を1つ選ぶ
2. `handoff.md` の Step 1〜3 を埋める（**Step 1 は渡さない**）
3. 評価役を独立起動して判定させる
4. **実際の結果と、評価役の判定を突き合わせる**

ここで「経緯を抜いたら、自分の判断が意外と根拠薄だった」と分かることが多いです。それが分かれば導入は成功しています。

## つまずきやすいところ

### 「評価役がいつもGOしか出さない」

ほぼ確実に、**経緯か願望が混ざっています。** `handoff.md` のStep 3チェックリストを上から順に確認してください。特に多いのがこの2つです。

- 「〜だと思うので評価してほしい」と書いている
- 不利な数字（実績ゼロ、損失、フォロワー数ゼロ）を省いている

### 「生成役が当たり障りのない案しか出さない」

**裏取りを求めていないか確認してください。** 「根拠のある案を」「実現可能なものを」といった条件を付けると、その瞬間に既存の案しか出てこなくなります。

生成役の出力は**外れていていい**という前提を、指示書に明示的に書き直してください。

### 「案は出るのに何も実行されない」

`executor.md` を導入していないか、3日ルールを守っていない可能性が高いです。**3日で作れない時点で、その案は分割するか見送る**のが原則です。「もう少し設計を詰めてから」で止まったものは、ほぼ戻ってきません。

### 「役が多すぎて管理しきれない」

**生成・評価・実行の3つから始めてください。** それ以上は必要になってから足します。役を増やすこと自体には価値がなく、**権能をまたがせないこと**だけが効きます。
